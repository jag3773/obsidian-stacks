# The road ahead

The destination is the whole journey: **collect → read → understand → write → cite**. Stacks covers each step of that path today. What comes next is making it work for more people, more devices and more kinds of libraries:

- **Highlights beyond PDFs.** Ebooks and documents are filed and linked today; bringing their highlights into notes, as Stacks does for PDFs, is still ahead.
- **Many devices.** Stacks is built to work with whatever sync you already use. Automated tests cover desktop Obsidian, its emulated mobile UI and the Android app on an emulator, but not iOS, real phones and tablets, or real sync services, and testing by hand on those has covered few setups. See [what is tested](sync-and-mobile.md#what-is-tested) and [mobile and offline reliability](https://github.com/jag3773/obsidian-stacks/issues/30).
- **Rougher edges of real libraries.** Probable duplicates (not just exact ones), several references in one pass of the citation picker, and capturing many results from a search page at once.
- **Your workflows.** What still sends you back to another reference manager decides what Stacks builds next.

The [feature backlog](https://github.com/jag3773/obsidian-stacks/issues?q=is%3Aissue%20is%3Aopen%20label%3Aenhancement) tracks proposals; it is a list to prioritize, not a promise. [PLAN.md](https://github.com/jag3773/obsidian-stacks/blob/main/PLAN.md) describes the design choices.

Obsidian already provides the workspace. Stacks builds on Web Clipper, Bases, the PDF viewer, and compatible plugins rather than recreating them. The aim is a coherent research workflow with your vault at its center.
